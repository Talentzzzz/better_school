# 跑腿订单先付后审

跑腿订单此前是先审后付（PENDING_REVIEW → PENDING_PAYMENT → PUBLISHED）：未支付的订单会占用人工审核资源，而通过同步初筛的订单支付即发布、完全没有人工把关环节。现反转为：创建时只做同步敏感词初筛（命中即失败、不落库），创建成功即待支付；支付成功（资金冻结）在支付事务内转入待人工审核；审核通过才对外可见（PUBLISHED），不通过打回退款（新增 REJECTED 终态 + 解冻）。审核裁决收敛为独立的用例接口（decide），人工与未来的 agent 审核共用同一签名，agent 以系统账号身份调用。

## Considered Options

- **保持先审后付**：审核资源被未支付订单占用，且免审核的订单付完款瞬间可见，人工把关形同虚设。否决。
- **支付后停在待支付、由 MQ 消费者转待审**：消息丢失或消费失败时，订单已付款却卡在"待支付"，需要额外兜底扫描才能自愈。否决——状态迁移跟着钱同步走，outbox 消息只承担通知职责和未来 agent 的接入点。

## Consequences

- 资金在审核期间处于冻结状态；待审期允许作者取消并解冻，审核拒绝走同一解冻路径（流水幂等）。
- PENDING_REVIEW 语义从"免付款的人工待审"重定义为"已付款待审"，超时扫描等既有逻辑随之调整。
- 同步初筛只覆盖文字（标题+描述），图片没有同步审核能力，完全依赖人工看图裁决。
