# 评论区树模型与两级平铺展示

评论区重构为楼中楼时，数据层采用 `root_id` + `parent_id` 双字段树模型：根评论两值皆 0；回复根评论时 `parent = root = 根评论 id`；回复楼内子回复时 `root` 恒为所在楼根评论 id、`parent` 为被回复的那条子回复 id，依此类推（数据上支持任意深度）。展示层永远两级平铺：整楼后代按 `root_id` 归组，仅当 `parent ≠ root` 时显示"▶ 被回复人昵称"指向标签（昵称取自 parent 行，忽略其状态）。

## Considered Options

- **纯两级模型（root + reply_to_user）**：查询更简单，但丢失完整回复链，指向关系无法还原到"回了哪条"，未来想做递归展示必须动 schema。
- **递归缩进 UI（Reddit 式）**：分页、渲染、缩进层级复杂度陡增，且参考产品（B 站）即为两级平铺 + 指向标签。

## Consequences

楼内子回复一律按 `root_id` 查询；楼内不再有"层级"概念，对话关系只通过指向标签表达。
