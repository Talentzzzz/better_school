# 资金链路收口：组合事务端口模式推广（ADR-0014 同库红利的全仓应用）

推广 ADR-0014 的根支柱到全仓资金链路。全仓事务边界扫描（2026-11-19）发现一批同型缺口：两个关键写
操作不在同一事务——跑腿支付「订单进大厅但悬赏没冻结」（余额不足也能发布成功，普通业务路径即可触发
的永久不一致）、取消/超时取消的悬赏永久悬置冻结态、送达 24h 自动完成的接单方收入永久不结算、商品
支付「买家从未扣钱、卖家却拿到钱」。既有重试基建（客户端重试、超时中心回调重投）会被终态幂等判定
吞掉——重试命中「已取消/已完成」直接返回，第二段资金动作永远不补跑。

**为什么是收口而不是补偿**：跑腿/商品与钱包同库同进程，ADR-0014 的「单在 ⇒ 分已扣」根支柱是物理
事务，不是状态表。中间态能被组合事务直接消灭的链路，建状态表 + 补偿 job 是负资产。全范围只有抽奖
「预扣 → 落库」一条真正跨物理事务（库存合并器 5ms 批量窗口是有意设计，不可并），才补对账 job。

## Decision

- **组合事务端口 = 基础设施层组件 `CompositeTxExecutor`**：一个 `TransactionTemplate`（REQUIRED）内
  编排多域动作，参与域仓储同为 REQUIRED 自动并入同一物理事务；任一步抛异常整事务回滚。消费方域在
  `domain/<域>/adapter/port/` 声明端口接口（判据留在消费方域，端口不放判据逻辑），实现落
  infrastructure 并经该组件编排；域 A 不写域 B 的表；case 层退为单次调用（禁令对 case 本身仍生效）。
  样板先例：marketing 侧 `PointsDeductPort`（ADR-0014）。
- **六条链路各自收口，不新增状态表、不新增资金补偿 job**：
  - 跑腿支付（票 02）：冻结流水 + 余额条件扣减 + 「待支付→已发布」条件翻转 + outbox + feed 索引行，
    一个物理事务；余额不足整事务回滚、订单留待支付。
  - 跑腿取消（票 03）/ 超时取消（票 04，开工场景另含信用分扣减）/ 自动完成（票 05，发布方解冻 +
    接单方悬赏收入 + 终态翻转 + 事件/feed/搜索 outbox）：状态翻转 + 对应资金动作一个物理事务；
    终态短路语义保留——重放读到终态直接返回，资金已随终态在同一事务内完成过，重投永远无害。
  - 商品支付（票 06）/ 取消（票 07）：同型收口（`PRODUCT_FROZEN` / `PRODUCT_UNFROZEN`）。
  - 确认收货与仲裁**不改**（终态短路回放结算结果的正面样板，已收敛）。
- **孤儿预扣对账 job（票 08）**：唯一跨物理事务的缝。扫台账流水 `flow_type=1 AND biz_type=
  'LOTTERY_DRAW'` 且 `biz_id` 无对应 `draw_record`、超 10 分钟的孤儿，登记进状态表
  `draw_orphan_prereserve_order` 后收敛：决策可重放→原幂等键重放落库后半段（奖品可能漂移，接受）；
  不可重放→库存回补 + 次数退还（`ORPHAN_REFUND`，桶 uk 幂等）。照 `drawCountPurchaseScan` 口径：
  cron 0/30、条件更新抢占、1/2/4/8/16 分钟退避、耗尽 DEAD 只 ERROR 日志。
- **流水先行 + 唯一键幂等不变**：所有资金动作仍以带唯一键的流水行落库，重复执行零副作用；唯一键
  吸收事务提交后响应丢失窗口的重复。
- **术语**：组合事务端口 / 孤儿预扣收敛 / 资金收口，见根目录 `GLOSSARY.md`。

## Considered Options

| 方案 | 为什么否 |
|---|---|
| 维持现状（终态幂等吞重试） | 第二段资金动作永不补跑；余额不足进大厅是普通业务路径即可触发的永久不一致 |
| Seata / TCC / 2PC | 同库单体用不到；无反向补偿需求；重量与收益完全不成比例 |
| RocketMQ 事务消息 | 回查要求本地状态表，省不掉任何东西，只多一跳 Broker |
| 为六条链路各建状态表 + 补偿 job | 同库红利下物理事务直接消灭中间态，状态表是负资产（ADR-0014 购买单是跨事务缝才需要） |
| 把确认收货/仲裁也改成端口收口 | 已收敛的正面样板，回放口径工作良好，强制迁移是无回归风险的负收益 |

## Consequences

**正向**

- 资金异常处置从例行人工 SQL 解冻变成真正的例外；「已支付必然带着真实冻结额」由物理事务保证。
- API 文档宣称（「支付（冻结悬赏），成功事务内转已发布」）与实现一致，文档停止漂移。
- `backend/CLAUDE.md` 跨域一致性纪律补上资金链路例外条款，后来者有据可依。

**负向（已接受）**

- 抽奖决策重放可能得到与原决策不同的奖品（漂移接受；原奖品预扣随之回补，守恒不破）。
- 死信仍是零自动信号（只 ERROR 日志 + 人工 SQL 重置），与 `alarm_email` 为空的现状一致。
- 六条链路各一条端口编排路径要维护；域服务与端口的职责边界（判据在域、编排在端口）靠纪律维持。
