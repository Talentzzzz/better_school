# 评论审核异步化（发布零同步审核）

评论采用先审后发，但发布接口不做任何同步审核：落库即 `PENDING_REVIEW`，同事务写 outbox 审核消息，由消费者异步执行敏感词检查（削发布峰值、发布路径零阻塞）。审核通过才转 `NORMAL`、才计入帖子评论总数、才发互动通知；不通过转 `REJECTED`、彻底消失并通知作者一条。作者本人始终可见自己审核中的评论，展示与正常评论无差别（无"审核中"标识）。这与帖子发布链路（同步敏感词）刻意不同：评论量大且碎片化，值得异步削峰；帖子量小、风险高，保持同步。

## Considered Options

- **先发后审**：发布即可见、不通过才下架——不良内容存在公开窗口期，与先审后发的产品口径冲突，否决。
- **发布时同步跑敏感词**（原实现）：阻塞发布接口、峰值风险，且与"发布秒回 + 乐观插顶"的体验目标矛盾，否决。

## Consequences

- 帖子评论总数为他人可见口径（仅 NORMAL 计入）；作者视角列表行数可能多于总数 N，属已知怪癖。
- 审核不通过不改变计数，因此不失效帖子详情缓存；审核通过/删除才失效。
