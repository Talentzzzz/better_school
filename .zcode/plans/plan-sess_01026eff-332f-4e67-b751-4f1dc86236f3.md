# 去除全部 SQL JOIN，改为仓储层多次查询拼装

## Context

全项目 SQL JOIN 集中在 mapper XML：better-school 9 个 XML（约 35 条语句、48 处 JOIN 关键字）+ marketing RaffleMapper.xml 3 条。Java 侧无注解/字符串 SQL（命中均为注释或 Thread.join()）。目标：SQL 层不再出现任何 JOIN，由 infrastructure 仓储层「主查 + 批量回查 + Java 拼装」替代——这正是仓库已有惯例（`CommunityRepository` L911 注释「为什么不在 SQL 里 JOIN」、chat 经 `IUserQueryPort.listByIds` 批量补昵称、评论列表经 `selectLikeCountsByIds` 回填）。语义（可见性谓词、热度排序、total 精确性）保持不变，HTTP 层集成测试断言不受影响。

## 四类通用改造模式

- **A. 昵称/头像 join bs_user** → 单表主查出 userId 集，`IUserDao.selectByIds` 批量回查，Repository 内存回填 PO/Entity 的 nickname/avatar 字段（字段保留，只是填充点从 SQL 挪到 Java）。
- **B. 计数窄表 join**（post_like_count/post_comment_count/post_view_count、product_view_count、errand_view_count）→ 新增各窄表的单表批量 statement（按主键 id 集 IN 查询），Repository 批量回填。
- **C. 关系表主行 join 业务表**（我赞过的/浏览历史/评论 tab/收藏/审核队列）→ 第一查：关系表单表取 id 集（带自身排序与分页）；第二查：业务表批量单表查；可见性谓词（state=NORMAL 等）从 SQL 挪到 Java（repository 内收口）；total 由「过滤后的集合大小」保证精确（每用户关系行有界）。
- **D. 上下文拼装**（父评论、来源帖标题、审核上下文、奖品台账）→ 逐表多查一次，Java 组装。

直查降级路径的 `hot` 档排序（现依赖 join 出的 view_count/like_count）改为：单表取过滤后集合 + 批量计数回查 + Java 内存排序后切片分页。

## better-school 改动（按 mapper）

| Mapper | 改法概要 |
|---|---|
| **PostMapper** | `selectById/selectByIds/selectPage 系`全部改纯 post 单表；新增 `selectLikeCountsByPostIds/selectCommentCountsByPostIds/selectViewCountsByPostIds`（窄表批量）；selectCountsByPostId 三窄表 join 改为仓储三次批量查；关系表语句（liked/commented/viewHistory/publicLiked 等 8 条）改两段查 + Java 可见性过滤，`countLikedByUser` 等计数同法；`rebuildFeedIndexProjection` 改 Java 装配（单表扫 post + 批量计数 + 批量 upsert 索引）；selectPage hot 档内存排序 |
| **PostCommentMapper** | rootCommentJoins 拆掉：作者经 `IUserDao.selectByIds` 回填；rejectReason 经 content_review 批量查（新增 `selectLatestRejectByTargetIds`，Java 取 max(id)）；`selectRepliesByRootId` 的父评论自连改第二查（`selectByIds`）；`selectPageByUser/countByUser` 的 JOIN post 改两段查；`selectById` 改单表 |
| **ProductMapper** | selectById/selectByIds/selectPage 系改纯单表；pvc 批量回查（新增 `selectViewCountsByProductIds`）；seller 信息回查 bs_user；`selectFavoritesByUser` 改两段查（product_favorite → product 批量）；rebuild 投影 Java 化；hot 档内存排序 |
| **ProductOrderMapper** | 3 条语句去 bs_user ×2 join：单表主查 + `IUserDao.selectByIds` 回填买卖双方昵称头像 |
| **ErrandMapper** | 同 Product：单表主查 + bs_user 回查 + view_count 批量回查（复用已有 `selectViewCount` 改批量）；rebuild 投影 Java 化；hot 档内存排序 |
| **NotificationMapper** | `selectPage` 改 notification 单表分页 + `selectLastReadSeq`（已存在）查水位，Java 算 isRead |
| **ChatMapper** | `selectRoomItems` 改三查：本人 room_member 行 → room 批量（新增 `selectRoomsByIds`）→ 对端成员行（已有 `listRoomMembers`），Java 拼装（沿用 ChatQueryServiceImpl 现有对家补齐口径）；`selectTimelineAfter` 改 timeline 单表扫描 + 新增 `selectMessagesByIds` 批量回查 |
| **ModerationMapper** | `selectReviewQueue/selectReviewDetail/selectTaskTargetDetail` 去业务表 join：review_task/content 单表后，ModerationRepository 注入 `IPostDao/IPostCommentDao/IProductDao/IErrandDao/IUserDao`（基础设施层允许多 DAO）批量回查素材与作者，INNER 语义用 null 过滤复刻；detailComment 的父评论/来源帖上下文二次回查；`selectRejectReasons` 自连派生表改 content_review 批量查 + Java 取每 target 最新；`selectReports` 昵称改批量回查 |
| **UserMapper** | `sumNormalPostLikeCount` 改：post 单表查该用户 NORMAL 帖 id 集 + 新窄表批量语句 SUM（Java 求和或 IN-SUM 单表语句） |

PO 类（PostPO/PostCommentPO/ProductPO/ProductOrderPO/ErrandOrderPO/NotificationPO/RoomListItemPO/TimelineMessagePO/ReviewQueueItemPO/ReviewTaskTargetPO/ContentReportPO）字段全部保留，仅注释改为「仓储回查填充」；domain 实体与 VO 不动，HTTP DTO 不动。

1. `selectPrizeCatalog`：`selectAwardListByStrategyId`（已有）单表 + 按 inv_id 集批量查 virtual/physical 台账（复用 inventory mapper 或新增批量语句），Repository 按 award_type 组装 pointsAmount/remaining/total/unlimited。

4. 测试内联 SQL：`DrawCountBucketIntegrationTest` L176 的 JOIN 改两次 jdbcTemplate 单表查询。

## 收尾

- 全仓 grep 确认 src/ 下（排除 target/）再无 SQL JOIN 关键字残留。
- 注释/文档口径同步：PO 与 mapper 内提到 JOIN 的 javadoc、`backend/better-school/docs/db/`（community/community_comment/chat/moderation/user.md）、`backend/docs/db/README.md`、`backend/docs/architecture/marketing-services.md` 中描述 join 语义的段落改为「多查拼装」口径。
- 集成测试本体不动（HTTP 级断言语义不变），仅改上述测试内联 SQL 一处。
