# 帖子审核重构 + 草稿箱 + 可选封面（含评论审核人工化）

术语遵循根目录 `CONTEXT.md` 的"同步初筛 / 先审后发 / 待审 / 草稿箱 / 审核未通过 / 编辑重审"等词条；本 spec 修订 ADR-0002（评论审核异步化）的口径。

## Problem Statement

从用户视角，现在的发帖/评论有四类问题：

1. **审核语义不自洽**：发帖命中敏感词被"静默"丢进待审（不报错，用户不知道发出去的东西去哪了）；而干净帖子却完全不经人工审核直接可见——"先审后发"名不符实。评论则是另一个极端：零初筛、发布即占人工队列、由机器消费者自动裁决，管理员对违规评论没有裁决权。
2. **没有草稿箱**：帖子写一半退出就全丢了；审核被拒即终态，想改只能从头重写。闲置商品已有完整的草稿箱+拒绝转草稿重提机制，帖子没有。
3. **封面不自由**：主页帖子卡片永远是"图+标题"，没图的帖子被渐变占位图填充，观感差；用户想发纯文字"小帖子"；封面锁死相册第一张，不能指定第几张、不能单独上传。
4. **审核员被动**：帖子/评论进入待审后没有主动通知，只能靠人工刷队列（跑腿、求购已有"进入人工审核"通知）。

## Solution

- **审核对齐闲置/跑腿**：帖子与评论统一为"同步敏感词初筛（命中报错不落库）→ 全部进入 PENDING_REVIEW 人工裁决（统一 decide 入口）→ NORMAL / REJECTED"。评论保留 outbox→MQ 链路，消费者从"自动裁决"降级为"通知审核员"（对齐求购支付后 notify 模式）。
- **帖子草稿箱**：复用 post 表加 `DRAFT` 状态，全套对齐商品草稿箱——拒绝转草稿、编辑重提（轮次+1）、待审撤回、24h 待审超时提醒；前端发布页/草稿编辑页退出弹窗存草稿，入口在"我的-发帖"左上角第一个。
- **可选封面**：post 表新增独立 `cover` 列——默认相册第一张，可改选任意一张，可独立上传新图（可不在相册中）；无封面（cover 与 images 均空）时主页渲染"标题+摘要"文字小卡（原型验证的 B 形态），feed 接口新增返回截断正文。

## User Stories

1. 作为发帖用户，我想帖子命中敏感词时立即收到明确报错且不落库，以便当场修改而不是发出去石沉大海。
2. 作为发帖用户，我想发布的帖子进入人工审核、通过后才对他人可见，以便校园内容有人把关。
3. 作为发帖用户，我想自己审核中的帖子只有我能看到且有"审核中"标识，以便随时了解帖子状态。
4. 作为发帖用户，我想在发布页写帖中途退出时被弹窗询问"是否存入草稿箱"，以便辛苦写的内容不丢。
5. 作为发帖用户，我想在草稿编辑页退出时同样被弹窗询问，以便草稿的修改也不丢。
6. 作为发帖用户，我想有一个草稿箱收纳未发布和被拒的帖子，以便随时回来继续编辑。
7. 作为发帖用户，我想草稿箱入口在"我的-发帖"左上角第一个，以便一眼找到。
8. 作为发帖用户，我想草稿编辑完整后一键提交进入审核，以便草稿成为正式帖子。
9. 作为发帖用户，我想草稿必填项不完整时提交被校验拦截并提示缺什么，以便不提交废单。
10. 作为发帖用户，我想帖子被拒后在草稿箱看到具体驳回原因，以便针对性修改而不是瞎猜。
11. 作为发帖用户，我想被拒帖子一键转草稿、改完重提（轮次+1），以便不用从头重写。
12. 作为发帖用户，我想重提后每一轮的审核记录都独立保留，以便回溯每一轮被拒的理由。
13. 作为发帖用户，我想撤回还在待审的帖子回草稿箱修改，以便发布前补救反悔的内容。
14. 作为发帖用户，我想帖子待审超 24 小时未裁决时管理员被提醒，以便帖子不被遗忘（不自动通过也不自动驳回）。
15. 作为发帖用户，我想默认用相册第一张图当封面，以便零操作获得正常的卡片展示。
16. 作为发帖用户，我想把相册里任意一张图设为封面，以便封面不被首图绑架。
17. 作为发帖用户，我想单独上传一张不在相册里的图当封面，以便封面与内容图解耦。
18. 作为发帖用户，我想不传图直接发布纯文字帖子，以便轻量表达（求助、失物招领一句话）。
19. 作为发帖用户，我想编辑草稿时也能改封面（换张/换图/取消封面），以便草稿完整可改。
20. 作为访客，我想主页纯文字帖渲染为"标题+摘要"小卡而不是占位图，以便信息流观感统一且能读到内容。
21. 作为访客，我想只有通过审核的帖子出现在主页 feed 和搜索结果里，以便看到的内容可信。
22. 作为访客，我想草稿、待审、被拒的帖子对非作者完全不可见，以便他人隐私不被泄露。
23. 作为评论用户，我想评论命中敏感词时立即报错不落库，以便当场改口。
24. 作为评论用户，我想评论进入人工审核且我自己可见（无标识），以便不被审核过程打断浏览。
25. 作为评论用户，我想被拒的评论我自己仍可见并看到驳回理由，以便知道它为什么消失且不反复踩坑。
26. 作为评论用户，我想重新发一条评论来表达修正后的内容，以便被拒后仍有出口（评论无草稿/重提）。
27. 作为审核员，我想在统一裁决入口按目标类型+轮次裁决帖子与评论，以便一套流程审所有内容。
28. 作为审核员，我想拒绝时必须填写理由，以便作者知道为什么被拒。
29. 作为审核员，我想同一目标的同一轮次裁决幂等（重复裁决不产生第二条记录），以便防误触。
30. 作为管理员/审核员，我想有新内容进入待审时收到通知（评论经 MQ、帖子靠队列+超时扫描），以便不靠轮询发现新任务。
31. 作为管理员，我想待审超 24h 的提醒按目标去重，以便不被重复轰炸。
32. 作为搜索用户，我想草稿/待审/被拒帖不出现在搜索结果，以便隐私与可信兼得。
33. 作为作者，我想删除自己的任意状态帖子（软删），以便清理不需要的内容。

## Implementation Decisions

### 状态机（帖子）

`DRAFT(0) → PENDING_REVIEW → NORMAL / REJECTED`；`REJECTED → DRAFT`（转草稿）；`PENDING_REVIEW → DRAFT`（撤回）；`DRAFT/REJECTED → PENDING_REVIEW`（提交/重提，轮次+1）；任意作者态 → `DELETED`（软删，维持现状）。直接发布（非草稿）轮次=1，草稿创建轮次=0（对齐商品语义）。

### 同步初筛语义变更

- 帖子发布：由"命中静默落库待审"改为"命中报错『内容包含违规词汇，请修改后重试』、不落库"，与商品/跑腿语义一致。
- 评论（根/回复）发布路径加入同一初筛（现状零同步审核），语义同上。ADR-0002 由新 ADR 修订：评论从"零同步+MQ 自动裁决"改为"同步初筛+人工裁决"，消费者降级为通知；原 ADR 记录的"评论量大削峰"理由失效，新 ADR 需说明统一人工把关的取舍。

### 异步人工裁决

- 复用统一裁决入口 decide（PRODUCT/WANT_TO_BUY/ERRAND/POST/COMMENT 已在队列 UNION）；POST 分支从"轮次恒 1"改为取业务表 `review_round`。
- 评论 outbox→MQ 链路保留：发布落库（待审）同事务写 outbox，消费者仅发"已进入人工审核"站内通知，不再做敏感词裁决（初筛已前移）。
- 帖子不引入 MQ（对齐闲置模式）：进队列可见 + 24h 超时扫描提醒即可。

### 24h 待审超时提醒（帖子）

新增帖子侧超时扫描 job（xxl-job 注册，模式对齐商品/跑腿）：扫描 `PENDING_REVIEW` 且 `review_entered_at` 超 24h 的帖子，发提醒给 ADMIN+AUDITOR，`dedup_key` 幂等（按目标+轮次），不自动裁决。

### Schema（单迁移文件）

- `post` 表：`cover` VARCHAR(500) NULL；`review_round` INT NOT NULL DEFAULT 1；`review_entered_at` DATETIME NULL；status 列注释补 `DRAFT`。存量数据无需回填（默认轮次 1 即正确）。
- `content_review` 复用现有 `uk_target_action_round` 幂等结构，无改动。
- 审核/通知复用现有表，无新表。

### 封面

- 请求 DTO 增加 `cover`（可空）：不传/为空 → 取 `images[0]`（存量与零操作路径兼容）；传了 → 存独立值，可与 images 无交集。
- 列表/详情的封面取值统一为 `cover ?? images[0]`；"无封面"= cover 与 images 均空。
- 详情页：有独立封面时顶部展示封面，相册（images）照常展示。
- 前端发布器：封面默认相册第一张，可点选任意一张，可单独上传新图，可清除封面（纯文字帖）。

### 文字小卡（原型结论）

主页无封面帖采用原型 B 形态：标题（2 行截断）+ 摘要（2 行截断）+ 作者/点赞行，自适应高度，与图卡混排瀑布流。feed 接口 `PostSummary` 新增返回 `content` 摘要（约前 50 字符，后端截断）。"我的"列表与搜索结果如涉及帖子卡片，同样区分图卡/文字卡。

### 草稿箱接口（对齐商品接口面）

- 保存草稿（新建）、编辑草稿、提交草稿（用例层完整性校验：content 必填、category 必填；title/images/cover 可空）、被拒转草稿、撤回待审。
- "我的-发帖"列表纳入 DRAFT 状态（仅作者可见口径不变）；草稿/被拒详情仅作者可见，被拒带 `rejectReason`。
- 前端退出拦截：发布页与草稿编辑页路由离开/页面关闭时弹窗询问存草稿。

## Testing Decisions

- **好测试的标准**：只测外部行为——HTTP 请求/响应、状态可见性、通知与幂等效果——不测用例内部实现。
- **Seam**：全部走现有 bs-app HTTP 集成测试 seam（真实 MySQL），不引入新 seam。已确认。
- **先例**：TradeDraftBoxIntegrationTest（草稿箱四态流转）、TradeRejectDraftAndEditIntegrationTest（拒绝转草稿重提+轮次+1+两轮记录并存）、TradeTakedownExpireRemindIntegrationTest（24h 提醒+dedup）、ErrandReviewQueueIntegrationTest（队列 UNION）、ReviewRoundMigrationTest（迁移校验）、PostCommentBaselineIntegrationTest（帖子/评论基线）。
- **覆盖面**：
  - 帖子：初筛命中报错不落库；先审后发全链路（发布→待审→通过可见/拒绝带理由）；撤回；拒绝转草稿重提（轮次+1、两轮审核记录并存、重提幂等）；草稿保存/编辑/提交/校验；24h 提醒 dedup；封面派生兜底（cover 空回退 images[0]、独立封面生效）；feed 摘要截断；文字帖无封面判定；搜索不同步非 NORMAL。
  - 评论：初筛命中报错；落库即待审；消费者改通知（不再自动通过/驳回）；人工裁决通过才计数+可见；被拒作者可见+理由。
  - 迁移：新迁移文件一个，迁移测试对齐 ReviewRoundMigrationTest 先例。
- 评论侧现有 CommentAsyncReviewIntegrationTest 按新语义改写。

## Out of Scope

- 已发布帖子的编辑（编辑重审语义）——后续票再对齐商品。
- 评论草稿箱 / 评论重提。
- 评论的 24h 待审超时提醒（本次只做帖子侧；评论量大，如堆积严重另立票）。
- 图片内容的审核（初筛只覆盖文字，与全站一致）。
- 跑腿/求购/商品审核的任何行为变更。

## Further Notes

- **原型**：卡片形态在主页路由以 `?variant=` 三变体验证（A 现状占位图 / B 文字小卡 / C 通栏细条），用户选定 **B**，并确认封面采用独立 cover 列（Q12-b）。原型代码（`front/src/components/prototype/` 下变体与切换器）实现时应收进 throwaway 分支保留，主分支只落胜者 B 的正式实现；实现票上留原型分支指针。
- **语义不对称说明**：评论有"进入审核"通知（链路已存在，消费者降级复用）而帖子没有（对齐闲置，不加链路）——这是刻意的成本取舍，不是遗漏。
- 存量数据：现有 NORMAL/PENDING_REVIEW/REJECTED 帖子默认轮次 1、无封面回退 images[0]，均无需数据修复脚本。
