# Map：分布式限流器 gatekeeper

_Label: `wayfinder:map`_

## Destination

一份 spec：`.scratch/gatekeeper/spec.md`——一个**通用分布式限流器**（客户端本地令牌桶 + 中心配额分配）的设计规格。覆盖：总体架构与一次请求的生命周期、租约与配额模型、中心的分片与高可用、规则模型与热更新、协议契约、降级与故障行为、可观测与验收口径、参考接入器的形状。**⚠️ 2026-09-22 [票 11](issues/11-task-write-spec.md) 已产出并收口**（Status: final；10 节 + 已知限制与未实测清单），本 effort 终点文档已落。

⚠️ **租约口径已由 [票 04](issues/04-grill-lease-model.md) 裁为速率租约**：中心下发"份额速率 + 有效期"，客户端本地桶按份额自补令牌（原表述"本地优先取令牌，不够时向中心批量领"是令牌口径，已作废）。

**不含** better-school 的业务改造步骤（spec 里只留"参考接入器"的形状），也**不含**落地票拆分——spec 定稿后另起 `.scratch/gatekeeper-impl/` 再拆，照 timeout-center / virtual-thread 惯例。

## Notes

### 图绘期的根决策（2026-09-22）

- **定位**：通用中间件作品，**不读写 better-school 的任何代码**（业务 key 只作示例）。工程落本仓顶层 `gatekeeper/`，将来要独立发布 `git subtree split` 即可拆出
- **形态**：三个 Maven 模块——`gatekeeper-api`（协议）/ `gatekeeper-center`（中心）/ `gatekeeper-client`（客户端 SDK）；**Java 21 + Spring Boot 3.3.5**，与本仓其余 4 个工程同栈（虚拟线程已落地，可吃红利）。⚠️ **2026-09-22 [票 10](issues/10-grill-reference-integration.md) 增补（细化非反转）**：再加第四模块 `gatekeeper-spring`（注解 + 拦截器 + 合一 starter，client 保持零 Spring 依赖）与演示模块 `gatekeeper-demo`。⚠️ **2026-09-22 结构修订（[ADR-0007](../../docs/adr/0007-gatekeeper-layering-and-protocol-module.md)）**：`gatekeeper-api` 已改名 **`gatekeeper-protocol`**（它是**线上数据契约 + 配置分发模型**，与 backend 的 `xxx-api`（服务行为契约）同名不同物）；**新增共享件 `gatekeeper-config`**（规则/拓扑配置源实现——两端都要连同一份配置，实现跨两端）；`gatekeeper-center` 再拆**内层 7 个 DDD 模块**；`protocol`/`config`/`client`/`spring` **不套 DDD**、`gatekeeper-demo` 只套两节——**工程共 6 个家庭层模块**。分层规范见 [`gatekeeper/CLAUDE.md`](../../gatekeeper/CLAUDE.md)
- **协议**：对外 **HTTP/REST（JSON）+ 批量租约接口**；**不引 Dubbo**（会把通用件绑死在 Java/阿里生态上）。v1 只出 Java SDK；"**协议即契约**"写进 spec（其他语言照协议自实现）
- **支持面按"调用边界"定义**：HTTP 入口 / RPC 调用边 / 业务代码里的显式 `acquire()` 都算。**MQ 消费与定时任务扇出是"不推荐接入"**（语义错配：拒绝一条消息 = nack → 重试 → DLQ 放大；job 扇出的施压者是自己的调度器，加限流只会让它变慢）
- **中心的一致性底座 = 多实例 + 按 key 分片**（中心之间不共享状态）；**Redis 只做规则存储/快照，不做令牌账本**（正确性不外包）
- **降级**：规则级可配，**默认 fail-open**（本地桶按已知规则自跑）
- **规则源**：抽象 + 双实现（Nacos / 本地文件）。客户端也必须知道规则，否则不能本地放行
- spec 含一节**参考接入器**（注解/拦截器/显式 API 的形状 + 一个能真拦下来的演示场景），但不含 better-school 里改哪几行

### 调研带回来的三条定位事实（各票要正面回应）

- **同形最近邻是 Envoy RLQS，不是 Doorman**（[票 01](issues/01-research-prior-art.md)）：协议级就是"客户端本地桶 + 中心下发带 TTL 的配额 + 客户端周期上报用量 + 服务端重算后主动推送"
- **"给已发出未消耗的额度设上限"，业界只有 Bucket4j 一家**；Doorman **承认 `shortfall` 存在**（仿真峰值 106%）并**明确放弃治理**（理由是治理会拖慢收敛）、Uber 干脆**废弃了本地令牌桶**改概率丢弃 ⇒ 图绘期"设上限（默认 2×）"这个决定是**逆主流**的，[票 04](issues/04-grill-lease-model.md) 必须连同票 03 的中心 QPS 账一起正面论证；若站不住，plan B 是"承认超发 + 靠短租约控制"（Doorman 路线）。**⇒ 票 04 已裁：论证结论是站不住（`B ≤ (λ−1)·K/(f·N)` 在 N=5000 下给 B<1），选了 plan B 的完整形态 = 速率租约，该机制撤销**（详见该票 `## Answer`）
- **中心的分片 / 选主 / 持久化没有业界答案可抄**：RLQS 无开源服务端实现、Sentinel 状态全在堆内存、Doorman 不持久化 ⇒ [票 06](issues/06-grill-center-sharding-and-ha.md) 这一块基本是自研，spec 要如实标注"无一手参照"

- [调研：业界"本地桶 + 中心配额"方案对照](issues/01-research-prior-art.md)：**最贴近本设计的不是 Doorman，是 Envoy RLQS**（协议级 = 客户端本地桶 + 中心下发带 TTL 的配额 + 客户端周期上报用量 + 服务端重算主动推送；用 `assignment_time_to_live = 0` 显式处理"中心重启前让客户端降级"）。**"已发出未消耗"设上限的只有 Bucket4j 一家**——Doorman 承认 `shortfall`（仿真峰值 106%）并**明确放弃治理**（治理会拖慢收敛），Sentinel 用 `exceedCount`/`maxOccupyRatio`，Uber **废弃了本地令牌桶**改概率丢弃。**配额分配三类口径**：Doorman 每请求重跑 `wants`/`gets`（`FAIR_SHARE` O(n²) / `PROPORTIONAL_SHARE` O(n)，`minF(gets, unusedCapacity)`）、Sentinel「单机阈值 × 在线连接数」（`AVG_LOCAL`）、DFMF 期刊滑动窗口预测 + 按比例重分；**自适应部分一律在客户端**（Doorman `AdaptiveQPS` 加权移动平均）。**降级**：Doorman 设计三档（pessimistic/optimistic/safe）但开源 Go 客户端**只实现 pessimistic**，Sentinel 默认 `fallbackToLocalWhenFail=true`（降本地单机限流），RLQS 不配即 fail-open，Stripe/Uber 显式 fail-open。**中心重启两条对立路线**：Doorman **不持久化不复制**、靠 learning mode 从一个 `lease_length` 内客户端自报的 `has` 重建（期间新客户端只能拿 0）；DFMF **主从 + 快照持久化**（论文图 6 崩溃后分发优于 Doorman）。⚠️ **证伪一条**：Netflix/Stripe/AWS **无** quota-leasing 一手支持，Uber 的废弃一说来自二手博客（未采信其公式）
- [调研：开源实现的可借鉴代码](issues/02-research-open-source-impls.md)：**Bucket4j 的"整数 long + 余数累加器（`roundingError` 存回状态）"补令牌 ⇒ 整数域零漂移、无 double，比 Guava 的 double 更适合本地桶**；且 **Bucket4j 已有"本地先花 + 攒欠账 + 超阈值才一次往返同步"的分布式形态**（`maxUnsynchronizedTokens` / `maxUnsynchronizedTimeoutNanos` 两个旋钮外露）= gatekeeper 的同形先例（javadoc 明说会超发）。**Envoy RLQS 的配额协议也是同形**：租约用 `assignment_time_to_live`（**时长**而非绝对时刻）、**策略没变只延 TTL 视为未变**（比 Doorman 每次续租整份重置更省）、`AbandonAction` 由"太久没上报"触发。**Sentinel 集群流控是反面参照**：无租约、无客户端 ID、无周期上报，每请求只换 `{flowId,count,priority}` ↔ `{status,remaining,waitInMs}`，客户端在册靠 Netty 连接 ⇒ "**连接在册可替代心跳上报**"（代价：中心不知道客户端本地余量）。**Redisson 拿客户端墙钟当 Lua 入参**（回拨无防护），且 `value` 只是缓存、对不上就 ZSET 全表重算 ⇒ **中心账本只留一个真相源**。Guava 的 `nextFreeTicketMicros`（锚"下一次可发放时刻"而非欠账计数器）与"`tryAcquire(timeout)` 先判能否过、不满足立刻 false"两条也可抄。⚠️ **纠正 [research/00](research/00-lease-reclaim-prior-art.md)**：Envoy RLQS 协议里**有** `AbandonAction`（服务端驱动、语义=弃桶），票 00"找不到任何实现"的措辞已放宽（结论不变）。⚠️ 全部为**静态源码阅读、未跑任何实现**；除 bucket4j 外各仓 commit SHA 未取到（GitHub API 限流），行号对应 2026-09-22 快照、会漂
- [调研：算法细节与陷阱清单](issues/03-research-algorithm-pitfalls.md)：**在飞量上界推导 + 三条对票 04 的硬约束**。上界（推导）：瞬时突发 ≤ `min{K+f·N·B, R·T+2K}`、在飞量 ≤ `min{f·N·B, R·T+K}`；**N 不进主导项**（R=1000/s、K=1000、T=10s、B=20 时 N 从 200 涨到 5000，突发只从 5×K 涨到 12×K）⇒「实例多了就雪崩」不成立。但**「在飞上限 = C×配额」能不能兜住突变，全看"配额"锚在哪**：锚 K 时 C=1 即"突发 ≤2K"有效；锚 R·T 时默认 C=2 = **放行 20 秒流量**，要压到 2 倍需 C ≤ 0.1（差 20 倍）。**可行条件 `B ≤ (λ−1)·K/(f·N)`**：N=200 时 B≤5（"一次领 20 个"与"突发 ≤2×"在 N=200 下**不能共存**），N=5000 时 B<1 ⇒ **机制直接失效**。**中心的租约 QPS 下界 = `N/(C·W)`，与 R 无关**（N=5000、C=1 ⇒ 5000 QPS/key，哪怕该 key 只有 1 QPS 流量）——在飞上限是把突发风险兑换成中心 QPS 的兑换器，不是免费保险。另三条硬约束：**幂等键**（POST 非幂等，超时重试必然重复领；键须客户端生成、每批一个新 UUID、重试复用；`clientId` 必须是"实例身份 **+ 世代号**"，否则崩溃重启的实例会让在飞量翻倍）；**fail-open 的本地速率必须是 `R/N` 而非 `R`**（否则分区期间 N 倍超发）；**心跳/上报必须按客户端聚合**（按 (key, 实例) 打点在 10k key×200 实例下是 200,000 QPS，聚合后 20 QPS ⇒ 批量接口是硬要求不是优化）。精度/时间源/容量账见票面。⚠️ **§4 整节为纸面推导、未实测**；**票 04 已选速率租约 ⇒ §4 整节作废**（连式 (5) 的 `min{…, R·T+2K}` 封顶一起），重推归 [票 12](issues/12-research-rate-lease-bounds.md)：原来的"用仿真复核三个算例"改为**按速率口径重推 + 仿真**。§1/§2/§3/§5 不受影响；§6.2 的"按租约条目记账不可行"要读成"选速率租约就要付这笔内存账"

- [grilling：租约口径（令牌租约 vs 速率租约）](issues/04-grill-lease-model.md)：**选速率租约**（Doorman / Envoy RLQS 同族，同形最近邻下发的是 `rate_limit_strategy` 而非令牌数）——中心下发"份额速率 + 有效期"，客户端本地桶按份额自补、容量 = 份额 × burstSeconds，**全局突发 = `R × burstSeconds`，与实例数无关**（⚠️ 2026-09-22 [票 12](issues/12-research-rate-lease-bounds.md) 乙案后精确形式 = `Σ max(份额 × burstSeconds, 1 请求)`，正常区间与原式相同）；令牌租约下突发 = `K + f·N·B`（票 03 式 (5) 的完整形态还带 `R·T + 2K` 的封顶；该式随 §4 一并作废）。**图绘期"在飞量上限默认 2×"反转撤销**——令牌口径下可行条件 `B ≤ (λ−1)·K/(f·N)` 在 N=5000 给 B<1，速率口径下由构造上界保证、不需要该机制。其余：上报只报实测三字段（RLQS 形状）、份额按 `PROPORTIONAL_SHARE`（O(n)）+ "绝不发出超过当前未用量"、在册靠续租请求自身（不加独立心跳）+ `clientId` 带世代号、续租"份额没变只延有效期"（RLQS）、账本单一真相源 + v1 不落盘（重启按均分保守发 + 重启前推 `ttl=0` 预告降级）、"过期作废退不退回"不适用。代价：中心内存 O(key × 在册实例数)。⚠️ 票 03 §4 整节作废 → 另立 [票 12](issues/12-research-rate-lease-bounds.md) 重推（已完成）

- [grilling：本地桶行为与放行语义](issues/05-grill-local-bucket-and-admission.md)：**本地桶 = 按份额自补的整形桶**，令牌用**微令牌整数**（Bucket4j 的"余数存回"手法；**不抄** Guava 的 `nextFreeTicketMicros`——我们**不欠账**）。**放行 API = `tryAcquire` → `Probe` + `acquire(timeout)`**（后者纯本地等；**放行路径零网络往返**，Q8 那条 Redisson 纪律因此退化到续租侧）。**每 key 一把 `ReentrantLock`**（不用 `synchronized`——虚拟线程会 pin 载体线程）。**时间口径 = `nanoTime` 差值 + 租约只传时长**；**到期行为 = fail-open（继续最后份额）**，⚠️ 但**主动 `ttl = 0` ⇒ 停止自补**——与"被动无响应"区分，否则 `ttl = 0` 退化成空操作（**本轮揪出的跨票不自洽，非反转**；"主动 `ttl = 0`"这一格是**我们的规定**、非 RLQS 原文语义）。**续租 = 每实例一条守护虚拟线程 + 一个批量请求 + 客户端侧抖动**；**冷启动 = 同步首租 + 合批** + 兜底三分法（无匹配规则 → 放行 / 有规则但首租失败 → 拒 / 曾断租 → 继续最后份额）；**冷 key 逐出整条**。红利：票 03 §5.4 的"fail-open 必须 `R/N`"在速率口径下**自动满足**。⚠️ 全部未落码（细节在该票 `## Answer`）

## Out of scope
