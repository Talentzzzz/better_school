# map — 闲置商品（先审后售）与求购（先付后审）的审核机制

spec: `.scratch/trade-review/spec.md`；词汇：`CONTEXT.md` 闲置商品一节 + 泛化后的"先付后审"；基础设施先例：`.scratch/errand-order-review/`（decide() / 初筛 / 钱包冻结 / 通知 / 管理端看图裁决 / 全链路测试基座均复用）。

## Notes

- 商品与求购**不同构**：商品走先审后售（无资金，DRAFT ⇄ PENDING_REVIEW → ON_SALE）；求购走先付后审（DRAFT → PENDING_PAYMENT → 支付冻结预算 → PENDING_REVIEW → NORMAL），机制复用跑腿、冻结标的是预算。
- 预算冻结规则：预算仅在求购对外可见（NORMAL）期间保持冻结；撤回、拒绝、下架、到期一律全额解冻退回，流水先行 + 唯一键幂等。
- 拒绝出路分岔：商品 REJECTED 可转草稿重提（轮次幂等承接第二次审核）；求购 REJECTED 是终态 + 退款 + 重新发布（对齐跑腿）。
- 编辑语义：待审不可编辑；商品改价生效、改内容回待审；求购改内容回待审（不重新支付）、改预算不支持；改内容重审期间对他人隐藏（不做内容版本化）。
- OFF_SHELF 废弃并入 DRAFT（存量迁移）；存量 ON_SALE / NORMAL 保持可见不回审。
- 通知：裁决结果（AUDIT_RESULT）+ 24h 超时提醒；求购支付后发"进入审核"通知（对齐跑腿），商品不发。
- 不做限流、不做图片同步初筛。

## Decisions-so-far

- （访谈定稿 v1，2026-09-06）商品与求购原计划同构走先审后售；REJECTED 终态、转草稿等决策基于"闲置无资金"前提。
- （访谈定稿 v2，2026-09-06）**求购路径反转为先付后审**（用户明确要求）：创建→同步初筛→创建成功→支付→支付成功进异步审核→审核通过对外展示。v1 中基于"无资金"前提的求购决策相应作废/改写：求购拒绝改终态退款（不再转草稿）、求购撤回先退款再进草稿、草稿提交进待支付而非待审。商品侧决策不变。
- （v2 定稿）Q1 冻结标的是求购预算（不是固定发布费）；Q4 求购支付走虚拟钱包、15min 超时取消、草稿箱保留在最前端；Q5"先付后审"泛化为跨跑腿/求购机制（CONTEXT.md 已改）；Q6 求购改预算 v1 不支持；Q7 预算仅在 NORMAL 期间冻结，离开可见态一律解冻。
- 测试 seam 定稿：完全复用跑腿票 07 基座（CommunityApiTestBase，HTTP + 真实 DB + 消费者/Job 直调），不新增 seam。
