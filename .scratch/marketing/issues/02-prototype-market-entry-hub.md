## 选型进展

### ④ 市集消息页 —— 定稿，用户已确认（2026-09-14）

**选 A，改成变体 D**（四轮修订：`01858bd` → `c922cd9` → `520316b` → `12fb64f`；截图 `market-msg-D-{errand,errand-thread,idle,idle-sell,want,empty}.png`）。**结构 = 外层三分类 + 分区竖排，无子 tab**：

1. **外层三分类与市集页同序**：跑腿 / 闲置 / 求购（原 A 是 闲置 / 跑腿 / 求购）。
2. **系统消息 = 一条会话入口**，形态与私信行同构：蓝圆铃铛 + 「系统消息」+ 最新一条预览 + **右侧竖排（时间 / 未读计数）**。**不显示「共 N 条」，也不就地展开**；点进去是**一个聊天框**（全屏、带返回），多条系统消息就是框里的多条气泡（气泡 = 标题 + 正文，日期分隔「近 7 天」）。三个 tab 都是这一条入口。
3. **条入口之下的内容按域不同**：
   - **跑腿**：`跑手消息` 摊开（对家在跑腿单里的角色恒为跑手）
   - **闲置**：**两个可选分类**（chips 切换，一次看一栏）`我买的`（对家=卖家） / `我卖的`（对家=买家）
   - **求购**：`卖家消息` 摊开（对家恒为卖家）

   系统消息 = 交易类系统事件（待支付 / 取消 / 支付入审 / 散团 / 审核未通过）；`跑手消息`/`卖家消息`/`我买的`/`我卖的` = 与对家的会话。
   闲置用「我买的 / 我卖的」而不是单一的「买家卖家」：用户明说闲置**要保留分类且可选**，跑腿 / 求购则去掉分类。

**用户 2026-09-14 看过最终原型后回「就是这个效果」——④ 定稿，后续不再改。**

**⚠️ 「系统消息做成一条会话」对后端有额外含义**：它意味着系统消息也要以「会话 + 消息流」的形态存在（有 room、有消息行），与私信共用聊天模型。而现有 `ORDER_EVENT` 通知是**一条条独立的 `notification` 行**，没有会话归并。票 07 定市集消息页数据源时要把这点一起定：是复用 chat 的 room/消息表造一个「系统会话」，还是把 `notification` 按域归并后伪装成一条会话。**→ 2026-09-14 票 07 已定：选后者**——`notification` 按 `scope` 归并、前端伪装成一条会话；**不落** chat 的 `room`/`message` 表。

**⚠️ 与票 01 §9 冲突，且有一个真实的表结构缺口**（`backend/sql/init.sql` 的 `room` 表）：

- `room.ref_type/ref_id` 的注释明写「**仅 GROUP 非空**（ERRAND=跑腿多人单，成团建群）；**1v1 为 NULL**」，唯一键是 `uk_direct_pair(user_min, user_max)`。
- ⇒ **跑腿的「跑手消息」现在就能筛**（多人单成团群的 `ref_type=ERRAND`）；但**闲置 / 求购的「买家卖家消息」筛不出来** —— 对家私聊全是 1v1，`ref_type` 为空，无法判断属于闲置还是求购。
- ⇒ 且 `uk_direct_pair` 决定**同一对人只有一条 1v1 会话**（跨商品复用），同一条会话可能同时在聊闲置 A 与求购 B。

**用户 2026-09-14 给的归属规则**：「**从市集里私信的消息就走市集里的消息，从首页进去的就走底部的消息**」。这等价于**按会话来源打标**：`room` 需要一个「来源」列（建立会话时写入）。落在票 07 的三条候选：

- (a) `room` 加 `biz_type` / `source` 列，1v1 首次由「私信联系」入口建会话时写入 —— 与用户规则最贴合，代价是**首个来源钉死**（同一对人先聊了闲置又聊求购，仍是同一条会话、同一个标签）。
- (b) 不做会话打标，改由**订单反查对家** —— 简单，但纯逛着聊、无订单的会话进不来，与用户「从首页进去走底部」的规则不贴。
- (c) 维持票 01 §9 原口径（市集页只做系统消息）—— 与用户本次指令冲突，除非推翻。

**票 01 §9 与票 07 ②③ 需同步改**：原写「市集消息页……**不含私信**（`uk_direct_pair` 只有用户对、没有来源域标记，强拆会让同一会话在两个页面重复出现或莫名消失）」——这段的理由正是本选定案要跨过的坎，改口径时要在两处一起写清「来源标记怎么来、首来源钉死怎么接受」。**→ 2026-09-14 已完成**：票 01 §9 已留 ⚠️ 反转注记、spec「市集消息页」节已写清（`room` 会话来源列 + 首来源钉死已接受）；票 07 三候选选 **(a)**。
