# 评论楼中楼重构（评论区 v2）

术语遵循根目录 `CONTEXT.md` 的"评论区"一节；架构决策见 ADR-0001（树模型与两级平铺）、ADR-0002（审核异步化）。

## Problem Statement

校园墙的评论区是纯平铺的：用户无法针对某条评论接话，多人对话只能靠"回复 xx："的文字约定，讨论无法成楼；帖子详情看不到评论总数，讨论热度只能靠翻评论感知；评论没有点赞，好内容无法被认可；被回复、被点赞的人毫无感知（没有任何通知）；匿名评论让对话双方身份混乱；发布评论后自己也不知道它处于什么状态。

## Solution

按参考图（B 站评论区形态）重构评论区：

- 楼中楼：数据上 root/parent 树，展示上根评论 + 平铺子回复 + "▶ 被回复人"指向标签，"展开 N 条回复"折叠/分页
- 帖子详情展示"全部评论(N)"，N = 根评论 + 子回复（仅他人可见口径）
- 评论（根与子回复）可点赞，评论区支持"最热 / 最新"两种排序（默认最热）
- 四类互动通知：帖被评、评被回、帖被赞、评论被赞
- 评论发布秒回（前端乐观插顶），审核异步执行，作者可见自己审核中的评论（无标识），他人审核通过后才可见
- 匿名概念整体移除（评论与发帖都实名）

## User Stories

1. 作为访客，我想在帖子详情看到"全部评论(N)"，以便不翻完评论就了解讨论热度
2. 作为访客，我想根评论分页加载，以便长评论区的首屏不至于过慢
3. 作为访客，我想按"最热 / 最新"切换评论排序，以便既能看高赞观点也能追时间线
4. 作为访客，我想在根评论下看到"展开 N 条回复"，以便知道这楼有后续讨论再决定点不点开
5. 作为访客，我想展开后楼内子回复平铺展示并带"▶ 被回复人昵称"，以便多人对话也能看懂谁在回谁
6. 作为访客，我想用"展开更多 / 收起"分页翻看长楼，以便长讨论不撑爆页面
7. 作为访客，我想每条评论和回复都显示点赞数，以便快速识别被认可的内容
8. 作为访客，我想审核中、未通过、已删除的评论不出现在我视野里，以便评论区干净可信
9. 作为登录用户，我想发表评论后立刻看到它出现在评论区顶部，以便确认发布成功不被阻塞
10. 作为评论作者，我想自己审核中的评论只有我能看到、且与正常评论展示无差别，以便不被打断地继续浏览
11. 作为评论作者，我想评论未通过审核时收到一条通知且该评论彻底消失，以便知道它为什么不见了
12. 作为登录用户，我想回复根评论，以便补充或回应楼主的观点
13. 作为登录用户，我想回复楼内任何一条子回复，以便精准接某个人的话
14. 作为登录用户，我想回复自动归入正确的楼（root/parent 由后端计算），以便不用手动选楼层、也无法伪造归属
15. 作为登录用户，我想在回复时看到"▶ 被回复人昵称"，以便确认自己在回复谁
16. 作为登录用户，我想被指向的评论后来被删/未通过时指向标签仍显示其昵称，以便对话上下文保持可读
17. 作为登录用户，我想给根评论或子回复点赞、再点取消，以便表达或收回认可
18. 作为登录用户，我想重复点赞不重复计数，以便点赞数可信
19. 作为登录用户，我想收到"你的评论被赞"通知，以便感知被认可（同一人对同一目标反复点赞只通知一次）
20. 作为帖主，我想有人评论我的帖子时收到通知，以便知道有人回应我
21. 作为被回复者，我想有人回复我的评论时收到通知，以便回去继续对话
22. 作为帖主，我想互动类通知在审核通过后才发出，以便点进通知一定能看到内容
23. 作为帖主，我想删除我帖子下的任何评论，以便维护自己帖子的评论区秩序
24. 作为评论作者，我想删除自己的评论，以便撤回反悔的内容
25. 作为评论作者，我想删根评论时整楼消失，以便我发起的讨论被整体撤回
26. 作为平台，我想删除是软删（隐藏而非物理清除），以便计数与楼层始终一致、内容可审计
27. 作为审核消费者，我想评论批量异步过敏感词，以便削发布峰值、发布接口零阻塞
28. 作为平台，我想通过的评论才可见才计数，以便评论总数等于真实可见评论数
29. 作为登录用户，我想所有内容实名展示（发帖与评论均无匿名），以便评论区可信
30. 作为发帖用户，我想发帖页不再出现匿名选项，以便不会误发匿名帖

## Implementation Decisions

**数据模型**

- 评论表新增 `root_id`、`parent_id`（BIGINT，默认 0；语义见 ADR-0001）、`like_count`、`reply_count`（仅根评论有意义），新增 `idx_root (root_id, status)`；移除匿名相关字段
- 新增评论点赞表：评论 id + 用户 id 唯一键幂等
- 帖子表移除匿名字段；通知表新增 sender_id（点赞通知按"点赞人 + 目标"去重的依据）
- 存量迁移：建表 SQL 原地更新，另出一份增量 ALTER 脚本供现有联调库执行；存量评论 root/parent 默认 0 即自然成为根评论，无需回填

**计数口径（全部同事务维护，评论与评论点赞是低频冷点，不走上 MQ 的削峰，与帖子点赞分级）**

- 帖子评论总数 = NORMAL 状态的根 + 子回复数（他人可见口径），审核通过时 +1，删除时按对应规则扣减
- 根评论 reply_count：楼内新增可见子回复 +1，删除 -1
- 评论 like_count：点赞/取消同事务 ±1，唯一键防重
- 已知怪癖（接受）：作者视角列表会多出自己的审核中评论行，行数可能大于总数 N

**发布与审核链路（ADR-0002）**

- 发布接口零同步审核：落库即 PENDING_REVIEW + 同事务写 outbox 审核消息，返回完整新评论 DTO 供前端乐观插顶
- 消费者异步跑敏感词：通过 → 条件 UPDATE 转 NORMAL（幂等）+ 计数 +1 + 失效帖子详情缓存 + 发互动通知；不通过 → 转 REJECTED + 给作者发一条通知，不失效缓存
- 人工审核队列与既有审核通过幂等机制沿用不动；帖子发布链路（同步敏感词）保持不变

**查询与展示**

- 根评论分页查询：`root_id=0` 且（NORMAL，或"是我且 PENDING_REVIEW"）；顺带修复列表 total 恒为 0 的既有缺陷
- 排序：默认最热（点赞数降序、同数按 id 升序），最新按 id 升序；楼内固定按 id 升序，不做双排序
- 楼内子回复：点开才拉取，默认 3 条、之后每页 10 条；指向标签昵称 JOIN parent 行取、忽略其状态
- 删除统一软删（用户删除与下架同轨，物理 DELETE 废弃）：删根 = 根转 DELETED、同事务扣减整楼可见数，子回复行不动；删子回复 = 仅隐藏该条、reply_count -1、总数 -1；权限沿用（评论作者或帖主）

**通知**

- 四类触发：帖被评（通知帖主）、评被回（通知 parent 评论作者）、帖被赞、评论被赞（通知作者）；自己评论/回复/点赞自己一律不发
- 互动通知在审核通过后发出；点赞通知按（sender + 目标）去重、取消赞不撤回已发通知；不做聚合（"xx 等 N 人"留作后续）
- 编排遵守项目约定：domain 服务禁止互相注入，跨域组合在 case 层顺序编排；通知写入失败只吞不回滚主流程

**API 契约**（base `/api/community`）

| 端点 | 语义 |
| --- | --- |
| `GET /posts/{postId}/comments?sort=hot\|new&page&pageSize` | 根评论分页；含作者自己的审核中评论 |
| `GET /comments/{commentId}/replies?page&pageSize` | 楼内子回复平铺 |
| `POST /posts/{postId}/comments` | 发根评论；响应含完整新评论 DTO |
| `POST /comments/{commentId}/replies` | 回复；root/parent 由后端按规则计算 |
| `DELETE /comments/{commentId}` | 软删；根评论删整楼 |
| `POST` / `DELETE /comments/{commentId}/like` | 评论点赞 / 取消 |

- 评论项字段：评论 id、作者 id/昵称、内容、时间、点赞数、当前用户是否已赞、（根评论）回复数；（子回复）被回复人 id/昵称
- 匿名参数从发布/查询链路整体移除；现有"我评论过的帖子"入口不受影响

**前端**

- 帖子详情页评论区拆分：评论区容器（总数 + 最热/最新 tab + 分页）、根评论项（回复/点赞/删除/展开 N 条回复）、楼内回复列表与子项（▶ 标签 + 展开更多/收起）、发表栏
- 发布成功乐观插顶（无标识）；匿名 checkbox 与"作者看自己匿名帖真实身份"逻辑一并移除

## Testing Decisions

- 好测试只测外部行为：HTTP 响应、可见的状态迁移、通知等副作用（以数据库可观察状态验证），不 mock 内部调用、不断言内部实现细节
- 单一 seam = trigger 层入口：HTTP 端点 + 审核消费者入口（测试中直接驱动消费者，不等 outbox 扫描定时器）
- 设施从零建立（仓库第一批测试）：spring-boot-starter-test + Testcontainers（MySQL、Redis 版本对齐 docker 编排），建库走初始化 SQL
- 覆盖：发布（作者视角可见/他人不可见/乐观插入数据来源）、列表（两种排序/分页/total 正确）、楼内回复（root-parent 计算正确性/防伪造/指向昵称/分页）、点赞（幂等/计数/通知去重）、删除（根整楼/子回复/权限/计数扣减）、审核通过与不通过（可见性迁移/计数/通知触发）、匿名移除后无回归
- 此测试设施与约定作为后续功能的先例

## Out of Scope

- 分享按钮、IP 属地展示、@mention 的解析/高亮/通知
- 点赞通知聚合
- 热评加权算法、评论搜索、评论进 ES
- 帖子发布链路与帖子审核方式的任何改动
- 评论编辑、评论配图、评论表情
- 历史匿名数据的身份保留（存量匿名标记随字段删除，历史评论实名展示；本地数据可重置）
