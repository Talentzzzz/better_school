# 07 prototype：审核中台 `front-review/` 可点原型

Type: prototype
Status: resolved
Blocked by: 无

## Question

用户明确要「**做个原型我看看**」。做一个**廉价、粗糙、可点**的审核中台原型，用来把「多类型同屏审核 + 推信号/拉工单的派单」这两件在设计上还模糊的事**逼成可以看的形状**，供后续票（05/06/08）做决策参考。**不是生产代码**，不进 `front/` 主工程。

要原型出来的东西：

1. **独立工程形态**：仓库新增 `front-review/`（Vue 3 + Vite，与 `front/` 同栈；构建/启动方式待票 08 定，先跑起来）。能 `npm run dev` 打开。
2. **多类型工单队列**：同屏展示帖子/评论/商品/求购/跑腿五类（mock 数据即可），可**按类型过滤/tab**；每条显示类型、摘要、等待时长；体现「一条一条审」的单条聚焦视图。
3. **单条工单详情**：内容素材占位（图文/配图网格/悬赏）、作者信息占位、历史裁决占位；**通过 / 不通过**（不通过要理由，理由用 `RejectReasonCode` 的枚举 chip + 可选补充说明，对齐现有 `ReviewWorkbenchView.vue` 的「理由口径全站统一」）。
4. **派单交互（本原型的关键）**：把「推信号 + 拉工单」做成**看得见**的——顶部「有新工单」提示（模拟推送信号）→ 点「拉一条」→ 工单进入「我的当前工单」并显示**租约倒计时**；处理完自动可再拉；租约到点自动回收回队列（前端模拟）。用来验证「推/拉结合」的交互手感是否成立。
5. **在线状态**：审核员在线/离线开关（手动模拟 presence）——验证「离线不推、上线补推」的表达。

**产出**：`.scratch/errand-lock-review-hub/prototype/`（或 `front-review/`，落点待定并在此记录）下的可运行原型 + 一页截图/要点说明，链接回本票。⚠️ 本票只解决「长什么样、怎么交互」，不解决数据模型与派单实现（那是 05/06）。

### 落点决定（票面要求「落点待定并在此记录」）
落在 **`.scratch/errand-lock-review-hub/prototype/`**，**不落**仓库根 `front-review/`。理由：本物是「廉价、粗糙、可点」的**原型**，票面自陈「不是生产代码，不进 `front/` 主工程」，与 effort 其余产物（issues / research / spec）同居语义最干净；且 **`front-review/` 的最终归位是票 08 的决策**（08 明写 `Blocked by: 07`）——08 若拍板独立工程，这套同栈脚手架可整体平移。

### 原型回答了票面的 5 件事（均可点验证）
1. **独立工程形态**：独立 Vite 工程，`npm run dev` 即开。
2. **多类型工单队列**：左栏同屏 **帖子 / 评论 / 商品 / 跑腿** 四类（mock），类型 tab 过滤，每条「类型徽标 + 摘要 + **已等待时长**」；FIFO 队首标「下一个」，体现「一条一条审」的前置视图。
3. **单条工单详情**：中栏**单条聚焦**——内容素材（图文 / 配图网格 / 悬赏 / 评论上下文）、作者信息（信用分 / 历史发布 / 违规次数 / 注册于）、历史裁决；**通过 / 不通过**，不通过用 `RejectReasonCode` **8 枚举 chip**（文案与 `front/ReviewWorkbenchView.vue` 及后端枚举一致）+ 可选补充说明（`maxlength=194`，对齐落库「枚举文案：补充说明」200 字口径）。热键 `A / R / Esc`。
4. **派单交互（关键）**：顶部**「有新工单」信号条**（模拟推送）→ 点**「拉一条」**→ 进入「手中」并起**租约倒计时**（原型取 **90s**）→ 审完**自动可再拉**；**租约到点自动回收回队列**（回收后保留原入队时间，等待时长继续累加）。右栏**派单事件流**把「进审 → 推送 → 拉取 → 裁决 → 回收」逐步记录——**把「推 / 拉结合」做成看得见**。
5. **在线状态**：在线 / 离线开关（presence 模拟）——**离线不推、新工单继续积压、上线补推**。

### 交给后续票的决策输入（原型暴露的设计问题）
- **05（派单）**：租约时长取值（原型 90s 仅演示回收）；**一次一条 vs 预取 N 条**（原型刻意「手里有单不能再拉」以检验压单 → 超时率手感）；拉取顺序（原型 **FIFO**，且 tab 只影响「从哪类拉」、不影响「拉哪条」，对齐「不做抢审」）；回收次数上限 / 反复超时的处置；presence 是否按内容类型分流。
- **06（数据模型）**：单条详情要的取数（内容素材 / 作者档案 / 历史裁决 / 风险标记）；「回收后等待时长继续累加」暗示的工单时序字段。
- **08（工程形态与部署）**：信息架构取「**左队列 + 中单条聚焦 + 右状态/事件**」三栏；桌面 Web（不做移动端响应式）；脚手架可直接平移至 `front-review/`。
- **map 的「Not yet specified」**：审核端信息架构已给出可点形状；「⚑ 风险标记」占位，具体形态待 06。

### 不做（与 map Out of scope 一致）
真实后端 / 网络 / WS 长连（presence、推送、claim、租约**全部在前端内存模拟**）；数据模型与 DDL（06）；派单算法与 Redis/DB 取舍（05）；登录 / 角色门控；移动端响应式。
