Type: grilling
Status: open
Blocked by: 01

## Question

计数从「精确」走向「近似」之后，谁负责回答「这个数为什么不对」，以及怎么修：

- **存量迁移**：窄表已有值，切到累加器要不要一次性 `COUNT(*)` 校准；切换瞬间存在「老消息还在 JVM 窗口里」的并发窗口，怎么排空。
- **重建**：`post_like_count` 从 `post_like` 全量重算的触发方式（管理接口 / 定时 / 手动 SQL），单轮成本与限速；评论点赞从评论点赞表重算。
- **对账读数**：累加器的「已扣未取走」量（Redis 里 Δ 的余额）要不要做成可观测指标，长期 > 0 即告警——对应库存侧的 `pendingDeductQty`。
- **偏差方向**：既定口径是「计数 ≤ 真实条数」，那出现**偏高**（现方案重启后重投会偏高）时告警还是静默修。
