# 12: `front-review/` 工程落地并接真链路

**Spec:** `.scratch/errand-lock-review-hub/spec.md` §5.4（工程形态与部署）、§5.5（原型结论）

**What to build:** 把审核中台从原型变成可用的独立工程，并接上真实后端。原型整体平移到**仓库根的新工程目录**（与主前端并列，源码 + 配置 + README 一起搬，**不带** `node_modules`/构建产物/增量缓存），技术栈与主前端一致（Vue 3 + Vite + TypeScript + SCSS、手写组件、无 UI 库）；独立 `package.json` / `tsconfig` / `vite.config`，`.gitignore` 补与主前端同款三行。

信息架构承原型：顶部**信号条** + **类型计数条**（只读）+ 主区**单条聚焦**工单（内容 / 作者 / 历史裁决 / 拒绝理由枚举 + 补充说明）+ 右栏**状态与事件流**；**仅桌面**。

把原型的离线假数据换成真链路：计数、领单、工单详情、裁决、放回，加审核长连接的派单信号与租约倒计时，交互闭环为「收到信号 → 拉一条 → 租约倒计时 → 审完可再拉 → 租约到点自动回收 → 回收后可再拉」。

工程形态与部署：开发端口独立、代理 `/api` 与审核长连接端点指向主后端；生产独立构建、静态产物发到**主站同一域名的子路径**（内网），反向代理同两个路径，**仅内网可达**（独立域名/端口会引入跨域与登录态搬运）。鉴权沿用既有登录令牌与角色门控，**不新建账号体系/SSO**；客户端路由守卫（非审核员/管理员跳主站登录）+ 服务端角色校验。不进 CI，独立版本、解耦发版；跨工程共享类型**手抄**（后端枚举为唯一事实源、两侧注释互指），**不引共享包/workspaces**（记为技术债）。
