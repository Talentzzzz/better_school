# 09: 裁决强绑定 + 遗留入口收口

**Spec:** `.scratch/errand-lock-review-hub/spec.md` §5.2「裁决写入——强绑定」「遗留入口收口」

**What to build:** 裁决只能由**持有人**对**自己手上的工单**做出，且「业务行已切 + 裁决已记 + 工单已关」三者原子。裁决用例：先断言当前工单确实由本人持有且处于租约中（不满足 → 403/409「请先领单 / 工单已被回收」），再按内容类型分发到既有裁决内核（**唯一内核不复制、不旁路**——沿用现成的通过/拒绝分支：域状态流转 + 审核记录 + 跨域资金动作 + 通知），最后**同事务**把工单置 `DONE` 并写裁决时刻，条件 UPDATE 带「持单人 + 租约中」双守卫。

**幂等（重试语义）**：重放时域方法命中 0 行、审核记录撞唯一键跳过、工单关单命中 0 行——整体幂等成功、零副作用，与既有超时回调同一口径。

**遗留入口收口**：既有的人工审核动作接口**不保留绕过路径**——改为按「类型 + 内容 id + 当前登录用户」反查其**持有的在途工单**，命中则转裁决用例，未命中 → 409「请先领单」，从而杜绝「不领单直接裁」。
