# 10: WS 连接层泛化 + `/ws/review` + presence

**Spec:** `.scratch/errand-lock-review-hub/spec.md` §5.3「presence」「推送通道」

**What to build:** 给审核端一条长连接通道，并让服务端知道谁在线。把既有私信长连接的**连接层骨架**抽出来复用（一次性票据鉴权、握手拦截、连接注册表、心跳判死、重复登录互踢、并发写保护），泛化到一个**新建的审核端点**上，并新增审核专属帧类型；**不复用原聊天端点**（其端点常量与帧类型写死了聊天语义），前端可复用既有长连接的客户端骨架（泛化票据接口、拆出聊天专属 handler）。

presence：审核端持长连按既有「心跳」口径探活（客户端固定间隔发 PING、服务端以任意入站帧刷新活跃时间、超时判死清理），在线集合落 Redis（可跨实例共享、可查在线人数、重启可恢复），**只收审核员/管理员**角色（角色过滤是新逻辑）。选 Redis 的理由是可查与跨实例，不是拿它做锁。

本票只交付「连得上、在线可见、断得掉」——派单信号的内容与推送时机见票 11。

**Blocked by:** None (can start immediately)
