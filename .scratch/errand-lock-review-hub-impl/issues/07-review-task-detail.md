# 07: 工单详情聚合 + 历史裁决

**Spec:** `.scratch/errand-lock-review-hub/spec.md` §5.1（多类型统一 / 历史裁决展示）

**What to build:** 审核员点开一条工单，一屏拿到裁决所需的全部上下文。详情取数是**中台聚合直查**（单体同库，不为各域造 RPC），沿用既有「按类型分支直查」的形态；素材差异用「通用列 + 类型专属上下文」表达——通用部分是内容、配图、作者（昵称/头像）、进入待审时刻、审核轮次；类型专属部分（跑腿的悬赏、评论的上下文）**不进工单列**，实时直查。

历史裁决同样一屏给出：**同一内容**的历轮裁决（重提前后各轮各自的结论与拒绝理由）与**同一作者**的历史裁决记录。为此给审核记录表加一列冗余作者 id（对齐既有举报表的先例），使「按作者聚合」单表可查、免 join；工单详情里的作者冗余字段也让基础信息免 join。工单只存定位与派单态，**不承载裁决与可见性**——对外可见与否由业务行状态流转决定，本票不引入任何新的可见性规则。
