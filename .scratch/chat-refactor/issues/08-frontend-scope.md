# 票 08：前端改造范围与过渡

## Question

手机端前端的改造范围与轮询→长连接的过渡：

- 现有 5s 轮询（`unread.ts` 总数轮询 + `ChatDetailView` 增量拉取）切到 WS 后，轮询接口是否保留为降级路径
- 会话列表/详情页的改造点；群聊 UI 范围（群成员列表？只做消息流？）
- 未读 store 与 WS 推送的融合（推送驱动的未读数更新）
- 手机端适配范围：现有 Vue 页面偏桌面布局，本次适配到什么程度

➡️ 产出：前端改造清单 + 过渡策略，供 spec 的接口清单与落地票拆分引用。

## Answer

（2026-09-09 grilling 结论，开放点用户全部拍板）

### 前置：票面前提修正 + 现状盘点

- **手机端适配前提过时**：票面写「现有 Vue 页面偏桌面布局」，勘察（front/）证伪——已是移动式布局（`index.html` viewport + `#app{max-width:480px}` + TabBar 底栏 + safe-area），无桌面残留。**无存量适配工作**，新页面沿用现有风格即可。
- 现状：定时轮询三处（`stores/unread.ts` 5s 求和未读总数 / `MessagesView.vue` 8s 会话列表 / `ChatDetailView.vue` 5s 增量拉 `afterId`）；全前端无任何 WS 代码；会话列表数据页面自持未进共享 store；鉴权 token 在 localStorage、axios 拦截器统一加 Bearer。

### 票面子问题与归属映射

| 票面子问题 | 归属 |
|---|---|
| 轮询接口是否保留为降级路径 | 本票 Q1 |
| 会话列表/详情页改造点 | 本票 Q2 + Q4 |
| 群聊 UI 范围 | 本票 Q3 |
| 未读 store 与 WS 推送融合 | 本票 Q2 |
| 手机端适配范围 | 前提过时，消解（见上） |

### 本票定案（用户全部按推荐采纳，两项改向已注明）

| # | 决策 | 结论 |
|---|---|---|
| Q1 | 轮询去留 | **定时轮询全拆**（三处定时器都不要），REST 拉接口本身保留（首屏、上滑分页历史、补拉）。断线期间消息延迟到达，重连补拉追平——票 04「推是加速拉是真相」的前端兑现；轮询降级与补拉兜底功能重复，留着「WS 可靠性」永远没被真正验证。否决保留降级轮询与「过渡期保留后期拆」 |
| Q2 | 未读/列表 store | **rooms 共享 Pinia store**：会话列表数据（含 unread/lastMsg）进一份 store，未读总数派生；WS MSG 推送就地更新对应会话（last_msg/未读+1/置顶重排），进详情页清该会话未读；列表页变纯渲染层。否决「只把未读数进 store、列表收到通知整页重拉」的旧模式 |
| Q3 | 群聊 UI 范围 | 消息流 + **只读成员列表页**（点顶栏进，纯展示无操作）：跑腿场景需确认「谁在单里」，被移除成员不可见（票 02）在此页体现 |
| Q4 | 详情页新交互 | 六项全做：① 发送乐观上屏 pending→HTTP 200 转正，失败/超时红叹号**手动**重发（复用同 client_msg_id，票 07）；② 长按自己消息弹菜单撤回（2 分钟窗口，票 06），就地变「已撤回」灰字；③ 图片复用 `/api/files/upload` 单条单图；④ 卡片发送入口=商品/帖子详情页「联系 TA」，会话内实时渲染+失效态；⑤ SYSTEM 消息居中灰字渲染服务端文案；⑥ KICK→提示「账号已在其他设备登录」→清 token 跳登录（close 4001 不重连，票 04） |
| Q5/Q9 | 已读回执展示 | 初稿「仅 1v1」被用户改向：**群聊全量做**（小群场景成员水位线直查性能可接受，票 07 已定 READ 推群不节流）。1v1：自己消息旁「已读/未读」小字，READ 到达就地翻转；群：**所有消息**（含他人消息）下方显示已读者头像（前 3 个+省略号），全部已读（按当前成员算，被移除者不计）显示「全部已读」四字，未全读显示头像；SYSTEM 消息不显示（居中灰字形态与头像条冲突）。已读判定=消息 seq ≤ 成员水位线，纯前端推导 |
| Q11 | 已读数据流 | **初始快照一次拉 + 增量推送就地更**：打开详情页拉一次成员接口（响应捎带 `last_read_seq`，与 Q3 成员页同源），READ 推送**载荷加 readerId** 就地更新成员水位 map。否决用户初稿「MSG 载荷捎带全员水位」（已读头像只在详情页渲染，打开时本来就要拉成员，每条 MSG 背 O(成员数) 水位是白背）；也否决纯拉（每次 READ 重拉）。**票 04 修订一处**：READ 从「只带定位」变「定位+readerId」，1v1 群统一（不再靠「只有两个人」推断读者），MSG/判重/对齐全都不碰 |
| Q6 | 会话隐藏入口 | **长按会话列表项 → 「删除该会话」**：本地立即消失，服务端置 hidden_at（票 01）；新消息 WS 推送到达时会话带着未读+1 弹回列表顶部——「新消息弹回」语义的直观呈现 |
| Q7 | delivery_seq 游标 | **内存持有不持久化**：刷新/重开进程 → 游标 0 → 全量补拉追平（timeline 永不删，0=全量永远正确，票 07）；localStorage 按 userId 持久化写为演进口（票 09） |

### 群会话可达性边界（Q8）

本次用户**没有任何进群入口**——群聊是系统群（票 05），跑腿多人单绑定是未来 effort（map Out of scope），群会话只由集成测试产生。前端群 UI 照做（渲染层与 1v1 共用同一批组件，含封盘只读态：输入框置灰「订单已结束」），可达性随绑定 effort 开通；测试验收靠后端造数。

### 前端改造清单（➡️ 产出，供票 09 接口清单与落地票拆分引用）

1. **WS 客户端（全新）**：App 级连接管理——登录即连/登出断开；先 REST 换一次性票据再连（60s 有效）；心跳 PING 25s；退避重连 1s×2 上限 30s；KICK 处理不重连。协议 C→S 仅 PING，S→C PONG/MSG/READ/RECALL/KICK（票 04）
2. **rooms store（全新）**：会话列表数据+未读+lastMsg 单一来源，total 派生；消费 MSG/READ 事件就地更新；`unread.ts` 轮询拆掉并入
3. **MessagesView**：纯渲染层 + 长按隐藏会话；群/单聊区分（群头像+群名）
4. **ChatDetailView 重写**：历史消息按 seq 游标分页（上滑加载更早，替代 afterId）；发送状态机（pending/转正/失败重发）；撤回菜单；图片/卡片/SYSTEM 渲染；已读小字与已读头像条；封盘只读态
5. **成员列表页（全新）**：只读，含 last_read_seq（水位线供已读头像推导）
6. **商品/帖子详情页**：加「联系 TA」入口带卡片发送
7. **KICK/登出处理**：提示+清 token 跳登录

### 接口清单波及（归票 09 spec 收口）

- threads 列表改造（room 模型：type/群名/preview/unread，替代现 thread 字段）
- 历史消息接口按 seq 游标分页（替代 `afterId`）
- 发送接口带 client_msg_id（票 07）；撤回接口（票 06）；隐藏会话接口；成员列表接口（含 last_read_seq + 成员数）；WS 票据接口
- READ 载荷加 readerId（票 04 轻推定义修订，见 Q11）
- 演进口：delivery_seq localStorage 持久化

前端遵循票 07 异常路径表既有结论：RECALL 轻推丢失接受退化（重进/重连呈现终态）、断线期间对方已读不补推（从 REST 读路径取水位线初值，与 Q11「打开拉一次」天然衔接）。
